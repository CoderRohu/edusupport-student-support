## 4. Bugs Discovered & Resolved During Development

1. **Type Resolution on Reopened State:**
   * *Issue:* The status transition workflow initially did not account for `Reopened` as an active status in dashboard count metrics.
   * *Resolution:* Updated metric aggregations in `/api/dashboard/stats` to classify `Reopened` as an active open ticket requiring staff action.
2. **Missing Resolution Notes on Ticket Closure:**
   * *Issue:* Marking tickets as `Resolved` could theoretically occur without documenting why or how the issue was fixed.
   * *Resolution:* Added mandatory validation on both client and server; if `status === 'Resolved'`, `resolutionNotes` cannot be empty.
3. **Internal Note Leakage Risk:**
   * *Issue:* A student inspecting network responses could view `internalNotes` if the full ticket object was serialized.
   * *Resolution:* Implemented server-side object sanitization in `store.listTickets` and `store.getTicketById` using destructuring (`const { internalNotes: _, ...safeTicket } = ticket`) before returning JSON to students.
